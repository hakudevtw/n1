# 同期プロトコル（schema 2）

サーバは無い。**クリップボードで JSON を往復させる**だけ。実装は `js/sync.js`（純関数）、テストは `tools/test-sync.js`。
このリポジトリは公開なので、ここには個人データを置かない（例はすべて架空）。

```
App ──「同期包をコピー」──▶ n1.sync ──▶ （チャットに貼る）──▶ コーチ
App ◀─「貼って確認→套用」── n1.coach ◀── （コーチが返す）◀────┘
App ──「完全バックアップをコピー」──▶ n1.backup ／ 「バックアップから還原」◀── n1.backup
```

共通の約束

- すべて `{"kind": "...", "schema": 2, ...}`。`kind` か `schema` が違えば拒否する。
- 貼り付けテキストの上限は **500KB**。``` で囲まれていても、前後に文章があっても、最初の `{` から最後の `}` までを読む。
- 貼り付けは**データ**として扱う。DOM には `textContent` と限定的な `**太字**` だけで出す（`innerHTML` に入れない）。
- 未知のフィールドは無視する。値の型・範囲は白名単で検査し、直す／捨てる。解析に失敗したら理由を出して、いまのデータには触らない。
- 日付は端末のローカル日付 `YYYY-MM-DD`。時刻は ISO 8601（UTC）か epoch ミリ秒（内部）。
- カード id: 単語 `w:<語>`、陷阱句 `t:<日>:<通し番号>`、文法 `g:<形>`。

## 1. `n1.sync`（App → コーチ、増量）

```jsonc
{
  "kind": "n1.sync", "schema": 2,
  "app": "n1-app v18",
  "id": "s-1793366000000",              // 匯出時刻（epoch ms）から作る識別子
  "exportedAt": "2026-10-30T13:13:20.000Z",
  "since": null,                        // 前回の匯出時刻（ISO）。初回は null = 全部入り
  "summary": {
    "today": "2026-10-30",
    "done": 15,                         // 今日答えた問題数
    "acc": 100,                         // 正解率 %。分母は done − わからない。分母 0 なら null
    "new": 11,                          // 今日の新詞（導入）数
    "reviewDue": 36,                    // 今日の到期（復習）枚数
    "learned": 161,                     // 学習中を含む全体
    "longTerm": 50,                     // 箱 4 以上
    "streak": 4,                        // 連続日数（今日まだなら昨日から数える）
    "gapDays": ["2026-10-20"]           // 直近 14 日のうち、何もしていない日（今日は含めない）
  },
  "days": { "2026-10-30": { "n": 15, "ok": 14, "new": 11, "rev": 4, "idk": 1 } },   // since 以降の日別集計
  "cards": { "w:例": { "b": 3, "due": "2026-11-06", "l": 1, "s": 6, "last": "2026-10-30" } },
         // 前回の匯出以降に変わったカードだけ。b=箱 due=次回 l=lapses s=出題回数 last=最後に答えた日
  "leeches": [ { "id": "w:例", "w": "例", "r": "れい", "m": "例子", "lapses": 4, "mt": { "audio": 2, "read": 1 } } ],
         // lapses ≥ 3、多い順に最大 40。mt = 間違えた出題型の回数（audio / read / mean / cloze / type / trap / quiz / form / gmean）
  "delayed": [ { "d": "2026-10-28", "n": 20, "ok": 17 } ],          // 延遲測驗、直近 5 回
  "log": [ { "t": 1793366000000, "id": "w:例", "q": "audio", "ok": "miss", "b0": 3, "b1": 1 } ],
         // 前回の匯出以降の作答、新しい 200 件まで。ok = "ok" | "miss" | "idk" | "known"（我熟了）
  "flags": [ { "t": 1793366000000, "id": "w:例", "q": "read",
               "snap": { "head": "読みを選ぶ", "prompt": "例", "opts": ["…"], "ans": 0 } } ],
         // 「這題怪怪的」。題面のスナップショット付き。ans は opts の正解位置（不明なら -1）
  "settings": { "newCap": 20, "mvdN": 20, "rate": 0.85, "theme": "auto" }
}
```

- **増量**: `cards` / `days` / `log` / `flags` は `since` より新しいものだけ。`since` は 1 つ前の匯出時刻。
- 貼れなかったとき: 「同じ区間をもう一度コピー」は **1 つ前の** `since` で作り直す（前回ぶんも含む上位集合。コーチ側は `cards` を id で上書きすればよく、冪等）。
- 60KB を超えたら設定ページに警告が出る。

## 2. `n1.coach`（コーチ → App）

```jsonc
{
  "kind": "n1.coach", "schema": 2,
  "id": "c-2026-10-30-a",               // 必須。冪等のキー。同じ id は 2 度適用されない
  "issuedAt": "2026-10-30T14:00:00Z",
  "settings": { "newCap": 12, "mvdN": 20, "rate": 0.9 },   // 任意。範囲外は丸める（newCap/mvdN 5–50、rate 0.5–1.3）
  "priority": ["w:例", "w:例二"],         // 優先詞（カード id）。未学のものだけ先頭に入る
  "notes": { "w:例": "**例文**で覚える" }, // カード id → 注解（最大 400 文字、**太字**のみ）。"" で消去
  "journal": [ { "d": "2026-10-30", "t": "今日は **よく続いた**。" } ],  // 歷程ページの教練の留言
  "message": "明日は 12 語だけ。"          // 今日ページに出る一言（最大 200 文字）
}
```

- 取り込む場所は白名単の 5 つだけ（`settings` / `priority` / `notes` / `journal` / `message`）。**カードの状態（箱・期日）は一切触れない**。
- 知らないカード id は無視（プレビューに件数を出す）。留言は `d`+`t` が同じなら重複しない。
- 流れ: 貼る → **プレビュー**（変わる設定・優先詞・留言・注解の件数）→ 確認 → **スナップショット**を取ってから適用。適用した `id` は記録され、もう一度貼っても何も変わらない（`適用済み`）。

## 3. `n1.backup`（完全バックアップ）

```jsonc
{ "kind": "n1.backup", "schema": 2, "app": "n1-app v18", "exportedAt": "…", "state": { /* 下記 */ } }
```

`state` ＝ 端末に保存している全部（`localStorage["n1app.v2.state"]`）:

| キー | 中身 |
|---|---|
| `schema` | 2 |
| `cards` | `{id: {box, due, lapses, seen, last, correctStreak, first, idk, mt{型:回数}, imp?, u?}}`（`u` = 最終更新 epoch ms。増量匯出用） |
| `days` | `{日付: {n, ok, new, rev, idk}}` |
| `log` | 作答ログ `[{t, id, q, ok, b0, b1}]`、環状バッファで最新 500 件 |
| `delayed` | `[{date, n, correct}]` |
| `journal` | `[{d, t}]`、`priority` `[id]`、`notes` `{id: 文}` |
| `flags` | 「怪怪的」記録、最新 100 件 |
| `ltm` | `{日付: 長期記憶の枚数}`（歷程の折れ線用） |
| `extra` / `times` | 今日の「再來 10 題」増分、読解の最速秒数 |
| `settings` | `newCap` 5–50 / `mvdN` 5–50 / `rate` 0.5–1.3 / `theme` auto・light・dark |
| `sync` | `lastExportAt` / `prevExportAt` / `applied[id]`（適用済みコーチ id、最新 100）/ `log[{t,k,s}]`（最新 50） |
| `coachMsg` | `{id, m, at}` または null |
| `savedAt` | 最後の書き込み epoch ms |

- 還原: 貼る → プレビュー（枚数・日数・書き出し日時）→ 確認 → **スナップショット**を取って置き換え。還原後の状態はバックアップの `state` を正規化したものと**完全に同じ**（`tools/test-sync.js`）。
- 読み込み時の正規化（`normalizeState`）は、型が壊れたカードを捨てて数える。旧開発版の `daily` / `newCap` も拾う。

## 4. 保存の安全策

- `localStorage` の壊れた JSON は**黙って初期化しない**。警告バナーを出し、保存を止め（上書きしない）、原文を `n1app.v2.corrupt` に退避し、スナップショット／貼ったバックアップからの復元を案内する。
- スナップショット: `n1app.v2.snaps`。最新 3 件。コーチ適用・還元・全部重設・大致會了の前と、1 日 1 回自動。
- `navigator.storage.persist()` を起動時に要求し、結果と `estimate()`、主画面（standalone）で開いているかを設定ページに出す。
